## Harness² 项目开工自动评估

用户已授权：对已有和新建项目，每项开发目标开工/恢复时自动评估；复杂任务或同一任务连续两次实现验证失败自动启动 Harness²；简单任务跳过四路实验，优先复用本项目经验。无需用户每次点名插件或再次确认启用。

**每个开发目标，包括只改一行的简单修改，都必须在首次写入前完成 `h2_context` 和 `h2_assess` 两次轻量调用并取得实际结果。simple 跳过的是四路实验，仍需记录开工评估。** 读取本条规则时不要仅在心里判断复杂度后直接修改文件。

1. 在首次实质实现前，结合当前任务、适用项目指令、当前目录/分支/工作树进行轻量判断；只定位当前项目（Git 根目录，非 Git 则已选工作目录），不扫描其它项目。先调用 `h2_context` 查看最近最多5个本项目目标与领域名；恢复同一目标时使用记录中的 task/domain 原文和 task_key，避免换措辞清零失败或重复建实验，不能把不同目标误合并。新目标选一个稳定领域 slug，优先复用本项目已有领域名。调用 `h2_assess`：`project` 为绝对项目根目录，`task` 为本开发目标的稳定描述，`domain` 为领域，`complexity` 为 `simple`/`standard`/`complex`，`signals` 为实际观察到的复杂度依据。一次开发目标始终沿用同一 task/domain/task_key；新目标重新评估。
2. 单点、明确、易验证的修改为 simple；有多个步骤但方案明确为 standard。跨模块行为与契约、困难算法、架构取舍等需要对比验证的任务为 complex，必须填写具体 signals。仅新建项目、多文件或常规安装本身不构成 complex。无需为普通问答/翻译/只读说明运行开发实验。
3. 先读评估返回的同项目、同领域、早于本任务且哈希验证通过的 `experiences`，按适用范围复用。`decision=skip` 时直接完成普通开发和检查，不创建四路实验。`decision=start` 时自动读取 `harness2-local:harness2` 技能并真正进入流程，准备可复现输入/检查器，调用 `h2_start`，带上 `assessment=task_key`，`task` 和 `domain` 使用评估返回值原文；继续完成一轮有界 k=1 比较及原任务，不只建议用户手动启用。`resume` 只继续缺失阶段；`reuse` 复用已验证结果并补齐缺失反思；`blocked` 保留失败/UNKNOWN/篡改证据并诊断，不默默重跑。
4. 对本目标每次实际的外层实现验证，调用 `h2_feedback`，提供 `project`、`task_key`、唯一 `event_id`、本轮实现的 `attempt_id`、`outcome`、简短 `check` 命令/退出结果摘要。同一次实现的 test/lint 等属于同一 attempt_id，合并为一个结果；分开记录也只计作一轮失败。修正实现并重新验证才是新一轮。实现验证失败用 failed；通过用 passed；认证/网络/环境阻塞用 blocked。两轮连续独立 failed 自动升级到 start，通过则清零；相同事件不能重复计数。不得伪造失败、把外部阻塞算作实现失败或保存秘密/完整日志。升级返回 start 后立即自动进入同一技能流程。
5. 原任务授权、项目所有权、用户未提交改动、验收与发布门禁继续有效。候选在隔离目录产出，检查使用同一冻结条件，默认每目标只一轮 k=1；不得自动扩大授权、改全局规则、跨项目共享经验或把本地实验当正式发布。状态和经验仅保存在本项目 `.harness2/`。实验内的探针/子执行不嵌套开新实验；明确的插件安装/规则维护任务也不递归自触发。
6. 当前会话若没有刷新出上述 MCP 工具，使用同实现 CLI，不把“工具未刷新”当作需再次授权：`python3 {{PLUGIN_ROOT}}/server/harness2_local.py --call <tool>`，通过 stdin 传同名 JSON 参数。技能入口：`{{PLUGIN_ROOT}}/skills/harness2/SKILL.md`。这是本机备用入口，不启动后台守护进程；没有任务时不运行实验。
